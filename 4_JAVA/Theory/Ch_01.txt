1.1 WHAT IS PROGRAMMING?
======================================================================

PROGRAMMING means writing a set of instructions that tells a computer
what to do.

A computer cannot normally understand human instructions such as:

    "Calculate my salary."
    "Find the largest number."
    "Display all students."

We must convert these requirements into instructions that the computer
can execute.

Example:

    Problem:
        Add two numbers.

    Human thinking:
        10 + 20 = 30

    Program:
        Take 10
        Take 20
        Add them
        Display 30


REAL-WORLD ANALOGY:

Think about a recipe.

    Human:
        1. Take two eggs.
        2. Break the eggs.
        3. Mix them.
        4. Cook them.

The recipe contains a sequence of instructions.

Similarly, a computer program contains a sequence of instructions:

    Input
      ↓
    Processing
      ↓
    Output


PROGRAMMING = Giving precise instructions to a computer.


======================================================================
1.2 WHAT IS A PROGRAM?
======================================================================

A PROGRAM is a collection of instructions written to solve a particular
problem or perform a particular task.

Example:

    Program:
        Read two numbers
        Add them
        Display result

A program can be very small:

    Hello World

or extremely large:

    Banking System
    Operating System
    E-Commerce Platform
    Airline Reservation System
    Railway Reservation System
    Enterprise Software


IMPORTANT:

Program ≠ Programming Language

Programming language:
    A language used to write programs.

Program:
    The actual set of instructions written using that language.


======================================================================
1.3 WHAT IS A PROGRAMMING LANGUAGE?
======================================================================

A PROGRAMMING LANGUAGE is a formal language used by programmers to
communicate instructions to a computer.

Examples:

    C
    C++
    Java
    Python
    JavaScript
    C#
    Go
    Rust
    Kotlin
    Swift

Each programming language has:

    1. Syntax
    2. Semantics
    3. Rules
    4. Keywords
    5. Data types
    6. Operators
    7. Control structures


EXAMPLE:

Java:

    int age = 25;

Here:

    int      → data type
    age      → variable
    =        → assignment operator
    25       → value
    ;        → statement terminator


======================================================================
1.4 WHY DO WE NEED PROGRAMMING LANGUAGES?
======================================================================

Computers fundamentally work with machine-level instructions.

Humans prefer:

    English-like syntax
    Mathematical notation
    Logical structures

Computers ultimately execute:

    Machine instructions

Programming languages provide a bridge.

    HUMAN
      │
      ↓
    Programming Language
      │
      ↓
    Compiler / Interpreter / Runtime
      │
      ↓
    Machine-level execution
      │
      ↓
    COMPUTER


Without programming languages, developing large software systems would
be extremely difficult.


======================================================================
1.5 LEVELS OF PROGRAMMING LANGUAGES
======================================================================

Programming languages can broadly be understood in levels.

    1. Machine Language
    2. Assembly Language
    3. High-Level Language


----------------------------------------------------------------------
1.5.1 MACHINE LANGUAGE
----------------------------------------------------------------------

Machine language consists of instructions represented in binary form.

Example concept:

    10110000
    01100001

The exact encoding depends on the processor architecture.

The CPU directly executes machine instructions.

Advantages:

    - Directly executable by CPU
    - Very low-level

Disadvantages:

    - Extremely difficult for humans
    - Processor dependent
    - Difficult to maintain
    - Difficult to debug
    - Difficult to write large programs


----------------------------------------------------------------------
1.5.2 ASSEMBLY LANGUAGE
----------------------------------------------------------------------

Assembly language uses symbolic instructions instead of raw binary.

Example:

    MOV AX, 10
    ADD AX, 20

An assembler converts assembly instructions into machine code.

    Assembly Code
          ↓
       Assembler
          ↓
    Machine Code


Assembly is easier than machine language but is still low-level and
hardware dependent.


----------------------------------------------------------------------
1.5.3 HIGH-LEVEL LANGUAGE
----------------------------------------------------------------------

High-level languages are designed to be easier for humans to read and
write.

Examples:

    C
    C++
    Java
    Python
    C#
    JavaScript

Example:

    int a = 10;
    int b = 20;
    int sum = a + b;

This is much easier to understand than machine code.

1.6 WHAT IS JAVA?
======================================================================

JAVA is a high-level, class-based, object-oriented programming language
and platform designed to support portable and robust software.

Java was originally developed at Sun Microsystems.

Java's major idea is:

    WRITE ONCE, RUN ANYWHERE

This means Java programs are designed to be portable across different
systems through the Java Virtual Machine (JVM).


BASIC IDEA:

    Java Source Code
          ↓
        javac
          ↓
       Bytecode
          ↓
         JVM
          ↓
    Operating System
          ↓
       Hardware


This architecture is one of Java's most important concepts.

======================================================================

Java was designed to address several software-development challenges,
including:

    - Portability
    - Reliability
    - Security
    - Object-oriented development
    - Networked applications
    - Automatic memory management
    - Platform independence

Java became especially successful in enterprise and server-side
software.

======================================================================

Java originated at Sun Microsystems in the early 1990s.

known as "Oak".

The language was later renamed "Java".

Important people associated with the early Java project include:

    James Gosling
    Mike Sheridan
    Patrick Naughton

Java was publicly introduced in the mid-1990s.

Java became widely adopted because of:

    - Platform independence
    - Web support
    - Object-oriented programming
    - Strong libraries
    - Enterprise adoption
    - Developer ecosystem


IMPORTANT:

    Java was developed by Sun Microsystems.

    Oracle acquired Sun Microsystems in 2010.

Today Java is developed and maintained under Oracle's stewardship,
together with the broader Java community and OpenJDK ecosystem.

1.10 IMPORTANT FEATURES OF JAVA
======================================================================

Java is known for several important characteristics.


----------------------------------------------------------------------
FEATURE 1 — SIMPLE
----------------------------------------------------------------------

Java was designed to be easier to use than many lower-level languages.

It removes or simplifies several complicated features found in C/C++.

Examples include:

    - No pointer arithmetic
    - Automatic garbage collection
    - Simplified memory management
    - Large standard library


----------------------------------------------------------------------
FEATURE 2 — OBJECT-ORIENTED
----------------------------------------------------------------------

Java strongly supports Object-Oriented Programming (OOP).

Important OOP concepts:

    1. Class
    2. Object
    3. Encapsulation
    4. Inheritance
    5. Polymorphism
    6. Abstraction

Example:

    class Student {
        String name;
        int age;
    }

Here:

    Student → class
    name   → field
    age    → field

Later we can create objects:

    Student s1 = new Student();


----------------------------------------------------------------------
FEATURE 3 — PLATFORM INDEPENDENT
----------------------------------------------------------------------

This is one of Java's most important features.

Traditional compiled languages often compile directly to native
machine code for a particular architecture.

Java normally follows:

    Source Code
         ↓
      Compiler
         ↓
      Bytecode
         ↓
        JVM
         ↓
    Native execution


Therefore the same Java bytecode can run on different platforms when a
compatible JVM is available.

For example:

    Windows
    Linux
    macOS

can all run Java programs using suitable Java runtimes.


IMPORTANT INTERVIEW QUESTION:

Q:
Why is Java platform independent?

ANSWER:

Java source code is compiled into platform-independent bytecode.
The bytecode is executed by a JVM implementation available for the
target platform.


----------------------------------------------------------------------
FEATURE 4 — PORTABLE
----------------------------------------------------------------------

Java programs can be moved between different systems with relatively
little platform-specific modification.

This portability is supported by:

    Java bytecode
    JVM
    Standard Java APIs


----------------------------------------------------------------------
FEATURE 5 — ROBUST
----------------------------------------------------------------------

Robust means Java is designed to help developers build reliable
software.

Java provides mechanisms such as:

    - Strong type checking
    - Exception handling
    - Automatic memory management
    - Runtime checks
    - Garbage collection


----------------------------------------------------------------------
FEATURE 6 — SECURE
----------------------------------------------------------------------

Java was designed with security in mind.

Important mechanisms include:

    - Type safety
    - Bytecode verification
    - Access control
    - Memory safety
    - Security APIs

Modern Java application security additionally depends on frameworks,
libraries, operating-system controls, network security and secure
development practices.


----------------------------------------------------------------------
FEATURE 7 — MULTITHREADED
----------------------------------------------------------------------

Java has built-in support for concurrent programming.

A THREAD is a unit of execution within a process.

Example:

A web server may simultaneously handle many requests.

Java provides:

    Thread
    Runnable
    Callable
    ExecutorService
    Locks
    Synchronization
    Concurrent collections
    CompletableFuture


----------------------------------------------------------------------
FEATURE 8 — HIGH PERFORMANCE
----------------------------------------------------------------------

Java is generally faster than purely interpreted approaches for many
workloads because modern JVMs use techniques such as:

    - JIT compilation
    - Runtime optimization
    - Adaptive optimization
    - Efficient garbage collectors


JIT = Just-In-Time compiler.

The JVM can compile frequently executed bytecode into optimized
native machine code at runtime.


----------------------------------------------------------------------
FEATURE 9 — DISTRIBUTED
----------------------------------------------------------------------

Java provides extensive support for networked and distributed
applications.

Examples:

    - Networking APIs
    - HTTP clients
    - Enterprise frameworks
    - REST APIs
    - Distributed systems libraries


----------------------------------------------------------------------
FEATURE 10 — DYNAMIC
----------------------------------------------------------------------

Java supports runtime behaviors such as:

    - Dynamic class loading
    - Reflection
    - Runtime linking

This allows applications and frameworks to perform certain operations
dynamically.

======================================================================
1.12 JAVA PROGRAM EXECUTION
======================================================================

Suppose we write:

    Hello.java


Source code:

    public class Hello {
        public static void main(String[] args) {
            System.out.println("Hello Java");
        }
    }


STEP 1 — SOURCE CODE

File:

    Hello.java


STEP 2 — COMPILATION

Command:

    javac Hello.java


The Java compiler converts the source code into bytecode.

Output:

    Hello.class


STEP 3 — BYTECODE

The .class file contains JVM bytecode.

It is not ordinary source code.

It is not directly the CPU's native machine code.


STEP 4 — JVM

Run:

    java Hello


The JVM loads and executes the bytecode.


COMPLETE FLOW:

    Hello.java
        │
        │ javac
        ↓
    Hello.class
        │
        │ JVM
        ↓
    Program Execution


======================================================================
1.13 WHAT IS BYTECODE?
======================================================================

BYTECODE is an intermediate instruction format generated by the Java
compiler.

Example:

    Java Source Code
          ↓
       javac
          ↓
       Bytecode
          ↓
        JVM
          ↓
    Native execution


Bytecode is important because it enables Java's portability model.


IMPORTANT:

    Source code ≠ Bytecode ≠ Native machine code


Source code:
    Human-readable Java program.

Bytecode:
    JVM-oriented intermediate instructions.

Native machine code:
    Instructions executed by a specific processor architecture.


======================================================================
1.14 WHAT IS JVM?
======================================================================

JVM stands for:

    Java Virtual Machine

The JVM is the runtime environment that executes Java bytecode.

It provides an abstraction over the underlying operating system and
hardware.

Basic architecture:

    Java Program
         ↓
      Bytecode
         ↓
        JVM
    ┌───────────────┐
    │ Class Loader  │
    │ Runtime Areas │
    │ Execution Eng.│
    │ JIT Compiler  │
    │ GC            │
    └───────────────┘
         ↓
     Operating System
         ↓
       Hardware


We will study JVM architecture deeply in a later chapter.

1.15 JDK, JRE AND JVM
======================================================================

These three terms are extremely important for Java interviews.


JVM:
    Runs Java bytecode.


JRE:
    Historically described as the JVM plus the runtime libraries
    required to run Java applications.


JDK:
    Development kit containing tools needed to develop Java programs,
    along with the runtime components.


Simplified relationship:

    JDK
    │
    ├── Development Tools
    │      ├── javac
    │      ├── java
    │      ├── javadoc
    │      └── other tools
    │
    └── Runtime Components
           └── JVM + libraries


IMPORTANT MODERN NOTE:

Modern JDK distributions do not necessarily ship a separately packaged
"JRE" product in the old sense.

For learning, remember the conceptual distinction:

    JVM → executes bytecode
    JRE → runtime environment concept
    JDK → development kit

======================================================================
1.25 JAVA VS C++
======================================================================

Since you are also learning C/C++, this comparison is important.

C++:

    - Compiles to native machine code
    - Supports manual memory management
    - Supports pointers and pointer arithmetic
    - Multiple inheritance of classes is supported
    - Very close to hardware

Java:

    - Compiles to bytecode
    - Runs on JVM
    - Automatic garbage collection
    - No direct pointer arithmetic
    - Does not support multiple inheritance of classes
    - Strong OOP model
    - Platform-independent bytecode execution model


CONCEPTUAL FLOW:

C++:

    C++ Source
        ↓
    Compiler
        ↓
    Native Executable
        ↓
    OS / CPU


Java:

    Java Source
        ↓
    javac
        ↓
    Bytecode
        ↓
    JVM
        ↓
    OS / CPU

1.27 WHAT DOES "WRITE ONCE, RUN ANYWHERE" MEAN?
======================================================================

Suppose you write:

    Hello.java

Compile it:

    javac Hello.java

You get:

    Hello.class


The bytecode can be used on:

    Windows JVM
    Linux JVM

assuming compatible Java versions/environment.

Therefore:

    Same bytecode
        +
    Platform-specific JVM
        =
    Platform portability


IMPORTANT:

It does NOT mean Java completely ignores operating-system differences.

The JVM implementation handles the platform-specific details.

1.29 LIMITATIONS OF JAVA
======================================================================

Java also has limitations.

    2. JVM startup overhead can matter in some workloads

    understand memory, performance and resource management.

ANSWER:

JVM stands for Java Virtual Machine. It provides the runtime
environment that loads and executes Java bytecode.


----------------------------------------------------------------------
Q5. What is JDK?
----------------------------------------------------------------------

ANSWER:

JDK stands for Java Development Kit. It provides tools required for
Java development, such as the Java compiler, along with runtime
components.


----------------------------------------------------------------------
Q6. What is JRE?
----------------------------------------------------------------------

ANSWER:

JRE historically refers to the runtime environment consisting of the
JVM and libraries needed to run Java applications. Modern JDK
distributions generally do not ship a separate JRE product.

Q8. What is the difference between Java and JavaScript?

They are different programming languages.

Java is widely used for backend and enterprise software.

JavaScript is widely used for web development and also for server-side
development using environments such as Node.js.

Java is strongly object-oriented and class-based, but it also has

1.38 COMMON BEGINNER MISTAKES
======================================================================

MISTAKE 1:

    "JVM compiles Java source code."

CORRECT:

    javac compiles Java source code into bytecode.
    The JVM executes/loads that bytecode.


MISTAKE 2:

    "Java directly converts source code into CPU machine code."

BETTER UNDERSTANDING:

    Java source
        ↓
    javac
        ↓
    Bytecode
        ↓
    JVM
        ↓
    Native execution/JIT as appropriate


MISTAKE 3:

    "JDK and JVM are the same."

WRONG.

    JDK → development kit
    JVM → runtime virtual machine


MISTAKE 4:

    "Java and JavaScript are related versions of the same language."

WRONG.

They are different programming languages.


MISTAKE 5:

    "Garbage collection means Java has no memory problems."

WRONG.

Java can still suffer from:

    - Memory leaks caused by retained references
    - Excessive object creation
    - OutOfMemoryError
    - Poor caching
    - High memory usage
