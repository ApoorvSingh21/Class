============================================================
3. WHAT IS A COMPILER?
============================================================

A compiler translates source code written by a programmer
into machine-understandable/object code.

Example:

C++ source:

    int main() {
        return 0;
    }

The compiler processes this code and produces lower-level
code that can eventually become an executable program.


Basic flow:

C++ Source Code
      ↓
Preprocessor
      ↓
Compiler
      ↓
Assembly
      ↓
Assembler
      ↓
Object File
      ↓
Linker
      ↓
Executable
      ↓
Operating System
      ↓
Program Execution

============================================================
8. WHAT IS PATH?
============================================================

PATH is an operating-system environment variable containing
directories where executable programs can be searched.

Suppose g++ exists at:

    C:\SomeCompiler\bin\g++.exe

If that directory is included in PATH, you can execute:

    g++

from a terminal without typing the complete path.


Without PATH:

    C:\SomeCompiler\bin\g++.exe program.cpp


With PATH:

    g++ program.cpp

14. USING C++ STANDARD OPTIONS
============================================================

C++ has different language standards.

You can explicitly select a standard.

Example:

    g++ -std=c++17 main.cpp -o main


C++20:

    g++ -std=c++20 main.cpp -o main


C++23:

    g++ -std=c++23 main.cpp -o main


Why specify the standard?

Because different C++ standards provide different
language/library features.


For job preparation:

    C++17
    C++20
    C++23

are useful standards to understand.

For interviews and competitive programming,
C++17 is still particularly common.


============================================================
15. IMPORTANT COMPILER OPTIONS
============================================================

Example:

    g++ -std=c++17 -Wall -Wextra main.cpp -o main


Meaning:

    -std=c++17
        use C++17

    -Wall
        enable many useful warnings

    -Wextra
        enable additional warnings

    -o main
        name output executable


Recommended learning command:

    g++ -std=c++17 -Wall -Wextra main.cpp -o main


For stronger diagnostics:

    g++ -std=c++17 -Wall -Wextra -pedantic main.cpp -o main


IMPORTANT:

Warnings are valuable.

A professional programmer does not simply ignore
compiler warnings.

16. SOURCE FILE
============================================================

A source file contains implementation code.

Common extension:

    .cpp

Example:

    main.cpp

Example:

    // employee.cpp

    int calculateSalary() {

============================================================
17. HEADER FILE
============================================================

Header files commonly contain:

    Declarations
    Class definitions
    Function declarations
    Templates
    Constants
    Interfaces


Common extensions:

    .h
    .hpp


Example:

employee.hpp:

    #ifndef EMPLOYEE_HPP
    #define EMPLOYEE_HPP

    class Employee {
    public:
        void display();
    };

    #endif


employee.cpp:

    #include "employee.hpp"
    #include <iostream>

    void Employee::display() {
        std::cout << "Employee";
    }


main.cpp:

    #include "employee.hpp"

    int main() {
        Employee e;
        e.display();
    }


Compile:

    g++ -std=c++17 main.cpp employee.cpp -o app


============================================================
18. DECLARATION VS DEFINITION
============================================================

Declaration tells the compiler that something exists.

Example:

    int add(int, int);


Definition provides implementation.

Example:

    int add(int a, int b) {
        return a + b;
    }


Header:

    int add(int, int);


Source:

    int add(int a, int b) {
        return a + b;
    }


This separation becomes extremely important
in large C++ projects.


============================================================
19. TRANSLATION UNIT
============================================================

A translation unit is essentially the source file after
preprocessing, along with the included contents needed
for compilation.

For example:

    main.cpp

after preprocessing may contain:

    main.cpp
       +
    included header contents
       ↓
    translation unit


Each source file can generally be compiled separately.


============================================================
20. OBJECT FILE
============================================================

After compilation, source code can be converted into
an object file.

Example:

    main.cpp
       ↓
    main.o


Another:

    employee.cpp
       ↓
    employee.o


Then:

    main.o
       +
    employee.o
       ↓
    Linker
       ↓
    executable


============================================================
21. LINKER
============================================================

The linker combines object files and libraries into
a final executable or library.

Example:

    main.cpp
    employee.cpp

Compile:

    g++ -c main.cpp
    g++ -c employee.cpp


Produces:

    main.o
    employee.o


Link:

    g++ main.o employee.o -o app


Now:

    app

is the executable.


============================================================
22. COMPILER VS LINKER
============================================================

Compiler:

    Source code
        ↓
    Object code


Linker:

    Object files
       +
    Libraries
       ↓
    Executable


Example linker problem:

    undefined reference to `Employee::display()'


Possible reason:

The declaration exists, but the implementation
was not linked into the final executable.

============================================================
28. COMMON TYPES OF ERRORS
============================================================

A. Syntax Error
B. Compilation Error
C. Linker Error
D. Runtime Error
E. Logical Error
F. Undefined Behavior


------------------------------------------------------------
A. SYNTAX ERROR
------------------------------------------------------------

Example:

    int main() {
        std::cout << "Hello"
    }


Missing semicolon.

Compiler reports an error.


------------------------------------------------------------
B. COMPILATION ERROR
------------------------------------------------------------

Example:

    int main() {
        unknownFunction();
    }


The compiler may report that the function
is not declared.


------------------------------------------------------------
C. LINKER ERROR
------------------------------------------------------------

Example:

    void display();

    int main() {
        display();
    }


If display() is declared but never defined,
the linker may report an undefined reference/symbol.


------------------------------------------------------------
D. RUNTIME ERROR
------------------------------------------------------------

Program compiles but fails during execution.

Examples:

    Invalid memory access
    Division by zero
    Unhandled exception
    Resource failure


------------------------------------------------------------
E. LOGICAL ERROR
------------------------------------------------------------

Program runs but gives incorrect result.

Example:

Expected:

    10

Program produces:

    20


The compiler may not detect this.


------------------------------------------------------------
F. UNDEFINED BEHAVIOR
------------------------------------------------------------

The C++ standard does not define what should happen.

Example:

    int arr[3] = {1, 2, 3};

    std::cout << arr[10];


Accessing outside the array bounds is undefined behavior.


IMPORTANT:

Undefined behavior is extremely important
for C++ interviews.

31. BREAKPOINT
============================================================

A breakpoint tells the debugger:

    "Pause execution here."


Example:

    int main() {

        int a = 10;
        int b = 20;

        int sum = a + b;   // breakpoint

        return 0;
    }


When execution reaches the breakpoint,
you can inspect:

    a
    b
    sum


============================================================
32. STEP OPERATIONS
============================================================

Common debugger commands/concepts:

    Continue
    Step Over
    Step Into
    Step Out
    Restart
    Stop


STEP OVER:

Execute current line without entering a function.


STEP INTO:

Enter the function being called.


STEP OUT:

Finish current function and return to caller.


CONTINUE:

Continue execution until next breakpoint/event.

============================================================
34. ASSERTIONS
============================================================

Assertions help detect programming assumptions.

Include:

    #include <cassert>


Example:

    int divide(int a, int b) {
        assert(b != 0);
        return a / b;
    }


If the assumption fails during a debug-oriented run,
the program can stop and report the failed assertion.


Assertions are useful for catching programming errors early.

47. FIRST PRACTICAL PROJECT
============================================================

Create:

    Calculator


Features:

    Addition
    Subtraction
    Multiplication
    Division


Structure:

    calculator/
    |
    +-- include/
    |     +-- calculator.hpp
    |
    +-- src/
    |     +-- calculator.cpp
    |     +-- main.cpp
    |
    +-- README.md
    +-- .gitignore


calculator.hpp:

    #ifndef CALCULATOR_HPP
    #define CALCULATOR_HPP

    int add(int a, int b);
    int subtract(int a, int b);
    int multiply(int a, int b);
    int divide(int a, int b);

    #endif


calculator.cpp:

    #include "calculator.hpp"

    int add(int a, int b) {
        return a + b;
    }

    int subtract(int a, int b) {
        return a - b;
    }

    int multiply(int a, int b) {
        return a * b;
    }

    int divide(int a, int b) {
        return a / b;
    }


main.cpp:

    #include <iostream>
    #include "calculator.hpp"

    int main() {

        std::cout << add(10, 20) << '\n';
        std::cout << subtract(20, 10) << '\n';
        std::cout << multiply(5, 4) << '\n';
        std::cout << divide(20, 5) << '\n';

        return 0;
    }


Compile:

    g++ -std=c++17 -Wall -Wextra \
        src/main.cpp src/calculator.cpp \
        -Iinclude -o calculator


Run:

Windows:

    .\calculator.exe

Linux/macOS:

    ./calculator

============================================================
49. DEBUGGING THE CALCULATOR
============================================================

Suppose:

    int divide(int a, int b) {
        return a / b;
    }


Potential problem:

    b == 0


A better design should handle invalid input.

For example, you might throw an exception:

    #include <stdexcept>

    int divide(int a, int b) {
        if (b == 0) {
            throw std::invalid_argument("Division by zero");
        }

        return a / b;
    }


This introduces an important professional concept:

    Error handling.


You will study this deeply in later chapters.

============================================================
53. COMPILATION TIME VS RUNTIME
============================================================

COMPILE TIME:

Time required to translate source code
into executable/object code.

RUNTIME:

Time during which the program executes.


Example:

    g++ main.cpp -o main

Compilation happens here.

64. IMPORTANT INTERVIEW QUESTIONS
============================================================

Q1. Is VS Code a C++ compiler?

Answer:

    No. VS Code is primarily a code editor.
    A separate compiler/toolchain is required.


Q2. What is g++?

Answer:

    g++ is the GNU C++ compiler driver used to
    compile/link C++ programs.


Q3. What is the difference between compiler and linker?

Answer:

    Compiler translates source code into lower-level/object
    code. The linker combines object files and libraries
    into an executable or other final binary.


Q4. What does -std=c++17 mean?

Answer:

    It requests compilation using the C++17 language standard.


Q5. What does -c do?

Answer:

    It compiles/assembles without performing the final link.


Q6. What does -o do?

Answer:

    Specifies the output file name.


Q7. What does -I do?

Answer:

    Adds an include search directory.


Q8. What is PATH?

Answer:

    An environment variable containing directories searched
    for executable programs.


Q9. What is a linker error?

Answer:

    An error occurring when required symbols/definitions or
    libraries cannot be resolved during linking.


Q10. What is a debugger?

Answer:

    A tool that lets you inspect and control program execution
    to find bugs.


Q11. What is a breakpoint?

Answer:

    A location where the debugger pauses program execution.


Q12. Debug vs Release?

Answer:

    Debug builds prioritize debugging and diagnostic information;
    release builds generally prioritize optimization and
    production use.


Q13. Why is CMake used?

Answer:

    To configure and manage builds in a portable and scalable
    way across platforms and toolchains.


Q14. Why should warnings be enabled?

Answer:

    They can identify suspicious or potentially erroneous code
    before runtime.


Q15. What is undefined behavior?

Answer:

    Behavior for which the C++ standard imposes no requirements.


============================================================
65. INTERVIEW TRICK QUESTIONS
============================================================

TRICK 1:

"Can C++ code run without compilation?"

Answer:

    Standard C++ source normally needs to be translated into
    executable/object code through an implementation/toolchain
    before execution. The exact process can involve interpreters,
    JITs, or other mechanisms in special environments, but that is
    not the normal native C++ workflow.


TRICK 2:

"Is compilation the same as linking?"

Answer:

    No.

    Compilation:
        source → object/lower-level code

    Linking:
        object files + libraries → final executable/library


TRICK 3:

"Does successful compilation guarantee a correct program?"

Answer:

    No.

    The program can still contain:

        Logical errors
        Runtime errors
        Undefined behavior
        Incorrect requirements


TRICK 4:

"Does a warning mean the program cannot run?"

Answer:

    Not necessarily.

    A warning is a diagnostic indicating something potentially
    problematic or noteworthy.
